# Installation and configuration

Local spelling rules also support optional probability (0–1, sampled independently per match) and kind. The default kind is literal. A repeated-negation rule matches a repeated 1–4 Han-character unit separated by source and emits target followed by that unit; place it before single-character mappings. A possessive rule asks the model to mark only clear ownership/attribute uses of source with a per-request marker, then the program resolves each marker using probability. Unmarked and uncertain uses remain unchanged; semantic recognition depends on the model. Code, quotations and exclusions remain protected. Nonliteral kinds cannot be combined with onlyBefore. Reload the Profile after changing engine code or prompts; rule JSON is read on every rewrite.

Read either README for requirements, local import and API setup. Install the local package using the Harness plugin manager and add dsh-plugin-kunming-dialect to the target Profile's dsh.profile.bundles list. The included cordis.patch.yml inserts its plugin row.

Set dbPath to an absolute path to your private SQLite database. Supported settings: transport (harness/openai), provider, model, apiBase, apiKeyEnv, timeoutMs, maxOutputTokens, intensity (light/medium/heavy), retrievalLimit (1–12), maxDraftChars, maxContextChars, retries (0–2), includeUnreviewed (boolean), and optional statusPath for a local startup report. Keep statusPath inside an ignored directory or outside the repository.

harness is the default transport. openai requires a Key in the environment variable named by apiKeyEnv. HTTPS is required except loopback development endpoints. Do not commit credentials or Profile configuration. The plugin does not load .env itself.

Windows scripts/install_profile.py now performs a read-only preflight. It never silently modifies installed QQ code. For the inspected QQ 0.5.3 layout, `python scripts/qq_compat.py PROFILE` prints source/config hashes and a migration plan. After reviewing an isolated Profile, use `--apply --expected-sha256 HASH` to remove only the known legacy whitelist modification and merge the three dialect tools into the supported `groupExtraTools` configuration. Existing tools, credentials, reply probabilities and persona are preserved. Unknown versions/layouts fail closed. The command snapshots both files, verifies writes, and rolls back on failure; `--restore BACKUP` restores only when post-migration hashes still match. This extension covers group sessions; non-owner private sessions need upstream support. Reload the Profile and inspect registration; no production messages are sent by this command. PyYAML is required for configuration validation (`python -m pip install PyYAML`).

For QQ, allow kunming_rewrite while retaining existing safety restrictions. Use showToolResults=false and streaming=false for this workflow. Restart/reload the Profile and confirm tool registration before group tests. A model may still skip the tool or emit earlier text. To disable the Bundle, remove its whitelist name at the same time: unknown whitelist names can mask all QQ tools in some customized installations.

Use `qq_compat.py PROFILE --disable` to review removal of the three dialect names, then repeat with `--apply --expected-sha256 HASH` before disabling the Bundle. Other tool permissions remain in place.

V0.2 adds `kunming_lookup` for local headword/alias/sentence lookup and `kunming_feedback` for explicit user teaching/corrections. Lookup exposes review status and does not infer that a similar word is authoritative. Candidate feedback stays pending in a separate `overlayPath` SQLite database. Set `feedbackScope` only on an instance dedicated to one trusted group; it is operator configuration, never a model-supplied group ID. Without both settings feedback storage is disabled. A shared multi-group instance must keep feedback disabled until the host provides a verified per-session scope. The installed long-term memory plugin exposes project scopes; project scope alone does not establish QQ group isolation, so this plugin does not automatically write member preferences into that store.

Local administrator commands: `node scripts/feedback.js DB SCOPE list`, `review ID corroborated [MEANING]`, `review ID rejected`, `review ID pending`, or `delete ID`. Confirmed feedback can supplement rewriting in its configured scope, but is always labeled user reported; it never updates dictionary tables or becomes dictionary verified. Model tools cannot approve or delete feedback. A boolean explicit-feedback assertion is a model guard, not proof of user consent; operators must review pending submissions.

Rewrites return `text` plus compatible `hits` and separate matching, candidate, example, claimed-ID, verified-ID, uncertain-ID and timing counters. Verification counts newly inserted exact multi-character headwords distinct from their Mandarin gloss, not full semantic adoption; existing words, common words, alternate spellings and syntactic influence need separate review. Malformed structured output falls back to the draft. Aggregate diagnostics default to a bounded JSON file under the database directory's `private/` folder; `diagnosticsMode` is `off`, `aggregate` (default) or explicitly enabled `private`, `diagnosticsPath` sets its location, and `diagnosticsRetention` caps records (1–10000, default 200). Aggregate mode omits message text and IDs. Delete the diagnostic file while the Profile is stopped to clear it, or use the diagnostics module's `clear()` method. Private mode retains drafts and candidates locally; keep every output ignored.

Run `scripts/evaluate-v02.ps1` for bounded real-model A/B evaluation using 120 original scenarios and a previously saved private baseline under `data/private/reports/v02-before/src/`. It checkpoints completed variants and refuses changed model/dictionary/prompt identities; repeat runs resume without recalling finished cases. `KUNMING_REFRESH_CASES=1` explicitly refreshes changed scenarios only and preserves the previous report. `node scripts/measure-retrieval.js` measures warm query counts/latency without model calls. `node scripts/relevance.js` exports private human-annotation templates; after labeling, pass the file path to calculate Precision@5/10 and Recall@10. Pooled judgments can miss unretrieved relevant entries. Real relevance and native naturalness remain unscored until human review. Reports stay in `data/private/reports/`.

Backups, local account credentials and imported datasets must remain private. No cloud or group test messages are sent automatically by npm test.

Optional `orthographyPath` points to a private JSON array of user spelling preferences. Each rule contains `source`, `target`, `excludePhrases` (an array), and optional `notes`. No real spelling dataset is bundled. The model receives these preferences; a final deterministic pass applies them outside protected code, URLs, quoted spans and excluded phrases. These preferences express user-selected approximate written pronunciation, not an assertion that a replacement character is the dictionary's canonical headword. Missing/malformed rules cause a controlled fallback. Native words with no suitable written approximation should be left unchanged.

Optional `includeExampleCandidates:true` admits all locally extracted `example_candidates` without falsely changing their review labels. `examplesPerEntry` defaults to 2 and supports 1–4. Stored examples take precedence; automatic examples from a folded duplicate can be retrieved through its canonical entry. Each selected example carries provenance. Older databases without this optional table continue to work. These switches affect eligibility, not bulk transmission: the configured retrieval limit and per-entry example cap still apply.
